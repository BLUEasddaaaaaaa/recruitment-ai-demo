# AI Studio 前端设计整理

## 整合结论

AI Studio 产出的是一套独立的 Vite + React + Tailwind 前端原型，已放入本项目的 `frontend/` 目录。它不是 Streamlit 主题皮肤，因此本次没有强行替换原有 Streamlit Demo，而是作为“新版前端设计原型”并入完整项目包。

当前项目包含两套可演示内容：

- `src/`：原 Streamlit Demo，功能链路完整，包含简历解析、HR 确认、候选人流程、AI 招聘运营助手。
- `frontend/`：AI Studio 设计的 React 前端，视觉效果更接近企业级 SaaS 工作台，适合后续作为正式前端重构方向。

## AI Studio 的设计思路

AI Studio 前端把产品定位为“智聘 AI 工作台”，核心设计语言是企业后台系统：

- 左侧固定导航：简历录入、候选人流程、AI 招聘运营助手。
- 顶部状态栏：页面标题、说明、当前时间、AI 引擎状态。
- 主工作区：用卡片、表格、状态标签和详情面板组织招聘流程。
- 强调 AI 能力：简历智能解析、低置信度提示、AI 待办、运营洞察、企业微信汇报。

## 三个页面设计亮点

### 1. 简历智能录入工作区

亮点：

- 提供简历文本粘贴、文件拖拽、示例模板。
- 点击 AI 解析后，展示结构化字段。
- 对姓名、电话、邮箱、岗位、部门、教育、经历等字段设置置信度。
- 支持 HR 修改后确认入库。

可借鉴到 Streamlit 的点：

- 低置信度字段用醒目标签提示。
- “AI 解析结果”和“HR 确认表单”分区展示。
- 上传区做得更像真实工作流入口，而不是普通文件控件。

### 2. 招聘台账全流程生命周期

亮点：

- 顶部筛选区包含岗位、部门、状态、HR，以及关键词搜索。
- 表格行可点击，选中后右侧展示候选人详情。
- 状态使用标签颜色区分。
- 面试记录作为历史时间线/记录列表追加。

可借鉴到 Streamlit 的点：

- 候选人流程页应以表格作为主视图。
- 选中候选人后再展示操作区。
- HR、岗位、部门、状态筛选要放在表格上方，形成“招聘台账”的感觉。

### 3. AI 招聘运营助手

亮点：

- 页面不只是统计图，而是展示 AI 待办、AI 洞察和一键汇报。
- 今日待办被放在最突出位置，强调“AI 告诉 HR 今天该做什么”。
- 企业微信汇报文案提供复制按钮。
- 洞察区用自然语言说明流程卡点、重点岗位和候选人积压。

可借鉴到 Streamlit 的点：

- 看板标题建议使用“AI 招聘运营助手”。
- 优先展示行动建议，而不是普通指标图。
- 汇报文案区域要适合复制到企业微信群。

## 与当前 Streamlit Demo 的关系

React 前端目前使用自己的 Express mock API 和内存候选人数据，不直接连接 Streamlit 的 SQLite 数据库。后续如果要正式融合，有两条路线：

1. 保留 Streamlit 后端逻辑，把 Streamlit 页面逐步美化为接近 AI Studio 的视觉。
2. 以 React 前端为正式界面，把 Python/SQLite 功能改造成 REST API 给 React 调用。

建议后续选择第 2 条路线：React 负责前端体验，Python 后端负责 AI 解析、数据库、流程记录和同步任务。

## 运行方式

原 Streamlit Demo：

```bash
./outputs/启动招聘AI-Demo.command
```

React 前端原型：

```bash
cd frontend
npm install
npm run dev
```

如需启用 Gemini，请复制 `frontend/.env.example` 为 `frontend/.env.local` 并配置 `GEMINI_API_KEY`。不配置时，前端服务会使用离线 mock 数据。
